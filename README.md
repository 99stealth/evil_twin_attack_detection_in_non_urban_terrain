# Evil Twin Attack Detection in Non-Urban Terrain

Machine learning pipeline for detecting Evil Twin Wi-Fi attacks from RSSI readings collected by four ESP32 sensors, and for localizing an ongoing attack (which point and which rogue antenna).

## Repository structure

```
data/
  rssi_raw.csv                    Raw labeled RSSI readings (long format)
src/
  eval_protocol.py                Single source of truth: dataset build, grouping, CV protocols, model configs
notebooks/
  01_eda_and_prototyping.ipynb    Data exploration + first pass at every model
  02_final_comparison.ipynb       Nested, session-aware CV benchmark + final results (paper figures/tables)
  03_protocol_comparison.ipynb    Shuffled vs. legacy vs. grouped CV, side by side (response-letter table)
  04_validation_robustness.ipynb  Locked hold-out, forward-chaining, dependence structure, bootstrap CIs,
                                   session/window aggregation, permutation tests, no-imputation variant
  legacy_tuning/                  Superseded per-algorithm tuning notebooks (see legacy_tuning/README.md)
results/                          CSV outputs of 02_/03_/04_ (regenerated by re-running the notebooks)
figures/                          Paper-ready PNG figures of 02_/04_ (no internal titles/model names)
  internal/                       Same figures with full titles (task + winning model + feature set)
```

### The notebook layers

1. **`01_eda_and_prototyping.ipynb`** — loads the raw CSV, visualizes the RSSI signal (baseline vs. attack windows), builds the synchronized `[s1, s2, s3, s4]` feature vector, and trains every model once at default/example hyperparameters. This is where the cascade task setup (Attack Detection → Point Prediction → Antenna Prediction) and the feature engineering idea are first introduced and explained.
2. **`legacy_tuning/*.ipynb`** — one notebook per algorithm (Random Forest, Extra Trees, XGBoost, LightGBM, CatBoost, Decision Tree, Logistic Regression, SVM, KNN), each doing a full `GridSearchCV` sweep plus diagnostics unique to it. **Exploratory only** — these use a shuffled `train_test_split`/`GridSearchCV(cv=5)` that leaks within-session samples (see [Evaluation protocol](#evaluation-protocol) below and `legacy_tuning/README.md`). Kept for transparency, not for reported numbers.
3. **`02_final_comparison.ipynb`** — the source of every number and figure reported in the manuscript. Runs nested, session-aware cross-validation (9 algorithms × 2 feature sets × 3 tasks) via `src/eval_protocol.py`.
4. **`03_protocol_comparison.ipynb`** — a focused side-by-side of the shuffled/legacy/grouped/LOSO protocols on two fixed models, written for the reviewer response letter.
5. **`04_validation_robustness.ipynb`** — the response to Reviewer 1's request for stronger validation without new field data: a locked final test set never touched by model selection (temporal block hold-out + a balanced session design), forward-chaining evaluation (train on the past, test on a later time block), a within-session dependence analysis (autocorrelation vs. ICC), cluster/session-level bootstrap confidence intervals, session-level and sliding-window result aggregation, a session-level permutation test, and a no-imputation sensitivity variant. See `results/VALIDATION_SUMMARY.md` for the consolidated numbers.

## Data

`data/rssi_raw.csv` is long-format: one row per sensor reading.

| column     | meaning                                                        |
|------------|-----------------------------------------------------------------|
| `time`     | reading timestamp                                                |
| `deviceID` | which sensor took the reading (`sensor_1`…`sensor_4`)            |
| `value`    | RSSI in dBm                                                      |
| `point`    | ground-truth location label (0 = no attack, 1–8 = attack point)  |
| `attack`   | binary attack flag (0/1) — target for Attack Detection           |
| `antenna`  | which rogue antenna was active (0 = none, 1–6) — target for Antenna Prediction |

All notebooks resample and inner-join the four sensors onto a common grid (5s by default, `freq` is a parameter) to build the synchronized `[s1, s2, s3, s4]` vector used as model input (see Section 4 of `01_eda_and_prototyping.ipynb`, or `eval_protocol.build_dataset`).

## Evaluation protocol

The experiment consists of 48 attack *sessions* (8 points × 6 antennas), each ~55s long
and resampled to ~11-19 rows on the 5s grid, separated by ~2min no-attack gaps. Rows
within a session are near-duplicates (RSSI std ≈ 1.2 dB, ~33% of rows at 5s are
nearest-neighbour imputed). A row-shuffled split or a shuffled K-fold therefore puts
near-identical rows of the same session into both train and test, letting a model
partly recognise the *session* instead of generalising — this is what inflated the
`legacy_tuning/` Point/Antenna numbers.

`src/eval_protocol.py` derives two group columns from the time-ordered raw labels
(`add_groups`): `session` (a run-length id over 48 attack sessions + 49 no-attack gaps)
and `block` (the antenna "block" of each session, gaps assigned to the next session's
antenna). All cross-validation is then grouped so that **no session ever appears in
both the train and test side of any split** (asserted at runtime in `nested_cv`):

| Task | Rows | Outer CV (primary) | Question it answers |
|---|---|---|---|
| Attack Detection | all | `LeaveOneGroupOut(groups=block)` — 6 folds | detect attack from unseen hardware / time block |
| Point Prediction | attack only | `LeaveOneGroupOut(groups=antenna)` — 6 folds | localize the attacker using an antenna unseen in training |
| Antenna Prediction | attack only | `LeaveOneGroupOut(groups=point)` — 8 folds | identify the antenna at a position unseen in training |

Hyperparameter tuning is nested: inside every outer fold, `GridSearchCV`
(`RandomizedSearchCV` for XGBoost/LightGBM/CatBoost, whose grids are too large for a
nested grid search) picks hyperparameters using `GroupKFold` on the same group type,
fit only on that fold's training data. Reported confusion matrices and accuracies are
built from the concatenated out-of-fold predictions across outer folds, so
`trace(CM)/sum(CM)` reproduces the reported accuracy exactly.

`03_protocol_comparison.ipynb` and `PROTOCOLS["loso"]`/`PROTOCOLS["legacy_unshuffled"]`/
`PROTOCOLS["shuffled"]` in `eval_protocol.py` provide the supplementary/robustness
protocols (leave-one-session-out, the old unshuffled 5-fold, and an explicit shuffled
5-fold leak baseline) reported alongside the primary numbers.

## Reproducing the paper figures

```bash
pip install -r requirements.txt
jupyter nbconvert --to notebook --execute --inplace notebooks/02_final_comparison.ipynb
```

This produces, from inside `notebooks/` (all paths relative to the repo root):

| Output | Content |
|---|---|
| `results/table1_primary.csv` | Table 1 — pooled OOF accuracy, fold mean±std, macro-F1, FE−Base delta |
| `results/per_fold_scores.csv` | per-outer-fold accuracy, every model × feature set × task |
| `results/best_params.csv` | per-outer-fold winning hyperparameters |
| `figures/fig4_comparison.png` | model comparison bar chart with error bars |
| `figures/fig5_n_estimators.png` | accuracy vs. `n_estimators` for each task's winning model |
| `figures/fig6_importance.png` | permutation importance, averaged over outer test folds |
| `figures/fig7_cm_attack.png` | OOF confusion matrix — Attack Detection winner |
| `figures/fig8_cm_point.png` | OOF confusion matrix — Point Prediction winner |
| `figures/fig9_cm_antenna.png` | OOF confusion matrix — Antenna Prediction winner |

Every figure is saved twice: the paper-ready version in `figures/` (no titles, no model
names — `plot_confusion(..., paper=True)` and the equivalent `paper` toggle in each
plotting cell) and the fully-annotated version (task + winning model + feature set in
the title) in `figures/internal/`, for internal review.

For the response-letter protocol comparison:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/03_protocol_comparison.ipynb
```

produces `results/protocol_comparison.csv`.

For the validation/robustness response to Reviewer 1:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/04_validation_robustness.ipynb
```

produces `results/final_holdout.csv` (V1, all 9 models per design, with a
`selected_on_dev` flag for the model chosen by dev-only nested CV), `results/v1b_test_sessions.csv`,
`results/forward_chaining.csv`, `results/baseline_stability.csv`,
`results/dependence.csv`, `results/main_table_ci.csv`,
`results/window_aggregation.csv` (now including detection rate/delay/recall alongside
the false-alarm rate), `results/permutation_tests.csv`,
`results/no_imputation_variant.csv` (both the `dropna_5s` and `scan_cycle` variants),
`results/localization_error_m.csv`, `results/VALIDATION_SUMMARY.md`, and
`figures/forward_chaining.png` / `figures/window_aggregation.png` /
`figures/permutation_antenna.png` (paper-ready; full-title versions in
`figures/internal/`). Its longest-running cell (the session-level permutation tests,
1000 permutations x 2 tasks) takes roughly 35-45 minutes; the full notebook takes
around 1-1.5 hours.

## Running the notebooks

Run everything from inside `notebooks/` so relative paths to `data/rssi_raw.csv`
resolve correctly (`eval_protocol._find_repo_root` walks up from the current working
directory looking for `data/rssi_raw.csv`, so it also works from `notebooks/legacy_tuning/`).

Recommended order:

1. **`notebooks/01_eda_and_prototyping.ipynb`** — explains the dataset, the resampling pipeline, and the cascade task setup.
2. **`notebooks/02_final_comparison.ipynb`** — the nested, session-aware CV benchmark. This is the longest-running cell (~9 models × 2 feature sets × 3 tasks of nested CV); expect a few minutes.
3. **`notebooks/03_protocol_comparison.ipynb`** — fast (no tuning), for the protocol side-by-side.
4. **`notebooks/04_validation_robustness.ipynb`** — the Reviewer 1 validation response; run after `02_`, since it reuses `results/table1_primary.csv` and `results/best_params.csv`. Slow (~30-45 minutes), dominated by the permutation-test cell.
5. **`notebooks/legacy_tuning/*.ipynb`** — optional, exploratory, superseded (see `legacy_tuning/README.md`).

To run a notebook non-interactively from the command line:

```bash
jupyter nbconvert --to notebook --execute --inplace notebooks/02_final_comparison.ipynb
```
